### 步骤 3：编写性能压测方案
在 `intellimes-backend/docs/performance-test-plan.md`：
- 压测目标：库存并发扣减 TPS、RabbitMQ 消息吞吐、AI 问答响应时间
- 压测工具：JMeter
- 压测场景：
  - 场景1：100 并发库存扣减，持续 5 分钟
  - 场景2：工单完工触发入库消息，1000 条消息吞吐
  - 场景3：AI 问答并发 50，响应时间
- 指标：TPS、平均响应时间、P95/P99、错误率、CPU/内存占用

### 步骤 4：执行库存并发压测
JMeter 测试计划 `inventory-stress-test.jmx`：
- 100 并发线程，每个线程循环调用出库完成接口
- 监控：TPS、响应时间、错误率
- 监控服务器：CPU、内存、Redis 锁等待、DB 慢查询
- 逐步加压：50 → 100 → 200 并发，找到系统瓶颈

### 步骤 5：执行 RabbitMQ 吞吐压测
- 批量触发工单完工（1000 个），测量消息消费吞吐
- 监控：消息积压、消费速率、消费延迟
- 调优：调整 `prefetch`、消费者并发数
- 输出吞吐量（条/秒）

### 步骤 6：执行 AI 问答压测
- 50 并发 AI 问答，测量响应时间
- 关注大模型 API 限流（429）
- 测量 RAG 检索耗时（ES 向量查询）与生成耗时

### 步骤 7：编写压测报告
在 `intellimes-backend/docs/performance-report.md`：
- 测试环境（服务器配置、Docker 资源限制）

- 性能瓶颈分析（DB 连接池、Redis 锁、ES 查询、大模型 API）
- 优化建议（连接池调优、缓存、异步、限流）
- 对比优化前后数据

### 步骤 8：性能优化（按需）

## 七、技术要点与注意事项
- **文档是交付的重要组成**：代码 + 文档 + 部署三位一体才是完整交付；README 是项目门面，运维手册保障线上运行，缺一不可。
- **压测找准瓶颈**：库存并发瓶颈通常在 DB 锁与 Redis 锁竞争；MQ 吞吐瓶颈在消费者并发与 DB 写入；AI 瓶颈在大模型 API 限流。压测目的是找到瓶颈并优化，而非追求高数字。
- **压测环境隔离**：压测用独立环境，避免影响开发；压测数据用专用数据库，避免污染开发数据。
- **简历亮点量化（计划书第八章）**：用数字增强说服力，如"50 并发库存扣减无超卖""RabbitMQ 消息吞吐 500 条/秒""知识库召回准确率 85%+"；避免空泛描述。
- **STAR 法则包装**：情境（业务背景）-任务（要解决的问题）-行动（技术方案）-结果（量化收益），每个亮点按此结构描述，面试时逻辑清晰。
- **面试问题准备**：分布式锁（Redisson 原理、锁续期、锁降级）、RabbitMQ（消息可靠性、幂等、死信）、RAG（分块策略、Embedding、混合检索、RRF）、Spring AI（ChatClient、流式），提前准备避免卡壳。
- **复盘价值**：总结做得好的（技术选型、架构设计）与不足的（监控缺失、测试不足），体现技术成长，面试时展示反思能力更受青睐。
- **持续优化方向**：微服务拆分（Spring Cloud）、K8s 编排、链路追踪（SkyWalking）、监控告警（Prometheus+Grafana）、CI/CD（Jenkins/GitHub Actions），作为项目后续演进方向，展示技术视野。
