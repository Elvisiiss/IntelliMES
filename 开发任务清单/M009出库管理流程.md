# M009: 出库管理流程

> **所属阶段**：第二阶段 - WMS 仓储模块
> **预计周期**：第 3 周
> **优先级**：P0
> **前置任务**：M008

## 一、任务目标
实现完整的出库管理流程：出库单创建→审核→完成状态流转，完成时先锁定 `locked_quantity` 再扣减 `quantity`，并写入 `inventory_log` 流水（change_type=2 出库），前端提供出库单列表与表单页面，与入库流程对称，跑通"单据驱动库存扣减"逻辑。

## 二、前置条件
- M008 已完成，InventoryService 增加 流程可用
- M002 中 outbound_order、outbound_order_detail 表已建好
- inventory 表已有库存数据（先完成入库）

## 三、详细执行步骤
### 步骤 1：编写出库单后端实体与 Mapper
- `entity/OutboundOrder`（orderNo、warehouseId、sourceType、sourceId、status、totalQuantity）
- `entity/OutboundOrderDetail`（orderId、materialId、locationId、quantity）
- `mapper/OutboundOrderMapper` + XML 联表分页查询

### 步骤 2：编写出库单 Service
`OutboundOrderService`：
- `createOrder`：生成出库单号 `OUT20260801001`，status=0 待审核
- `audit`：0→1 已审核，**关键**：审核时锁定库存 `InventoryService.lock(materialId, locationId, quantity)` 增加 locked_quantity
- `complete`：1→2 已完成，**关键**：扣减库存 `InventoryService.deduct(materialId, locationId, quantity)` 同时减少 quantity 和 locked_quantity，写流水 change_type=2
- `cancel`：
  - 0→3 直接取消
  - 1→3 已审核取消需释放锁定 `InventoryService.unlock` 减少 locked_quantity
- `pageQuery` 分页

### 步骤 3：扩展 InventoryService 出库相关方法
在 `InventoryServiceImpl` 补充：
- `lock(materialId, locationId, quantity)`：校验 `quantity - locked_quantity >= ?`，UPDATE locked_quantity += ?（乐观锁）
- `deduct(materialId, locationId, quantity)`：UPDATE quantity -= ? AND locked_quantity -= ?（乐观锁）
- `unlock(materialId, locationId, quantity)`：UPDATE locked_quantity -= ?
- 每个方法都用 `@Transactional`，校验库存不足抛 `BusinessException("库存不足")`

### 步骤 4：编写出库单 Controller
`OutboundOrderController`：
- `POST /wms/outbound/page` 分页
- `POST /wms/outbound` 创建
- `PUT /wms/outbound/audit/{id}` 审核（锁定库存）
- `PUT /wms/outbound/complete/{id}` 完成（扣减库存）
- `PUT /wms/outbound/cancel/{id}` 取消（释放锁定）
- `GET /wms/outbound/{id}` 详情

### 步骤 5：编写前端 API 与页面
- `src/api/wms/outbound.ts`
- `src/views/wms/outbound/index.vue`：列表 + 状态流转按钮
- `src/views/wms/outbound/form.vue`：表单，明细行选择物料时显示当前可用库存（quantity - locked_quantity）

### 步骤 6：联调验证出库流程
- 先确保 M001 螺丝在 A1-01 有 100 个库存
- 创建出库单（明细：M001 螺丝 30 个 货位 A1-01）
- 审核：查 inventory 表 locked_quantity=30，quantity 仍为 100
- 完成：查 inventory 表 quantity=70，locked_quantity=0
- 查 inventory_log 有 change_type=2 记录

### 步骤 7：库存不足边界测试
- 创建出库单明细数量为 200（库存只有 70）
- 审核时返回"库存不足"异常
- 创建出库单 50，审核后再审核另一张 50（共需 100，库存 70）
- 第二张审核失败（available = 70-50=20 < 50）

## 五、预期产出
- 完整出库单生命周期（创建→审核锁定→完成扣减→取消释放）
- 库存锁定机制（locked_quantity）防超卖
- 前端出库单管理页面
- 与入库流程对称，构成 WMS 出入库闭环

## 六、验证方式
- 创建出库单 status=0，审核后 status=1 且 locked_quantity 增加
- 完成后 status=2，quantity 减少、locked_quantity 减少、inventory_log 有 change_type=2
- 已审核取消后 locked_quantity 释放回 0
- 库存不足时审核返回业务异常
- 前端表单选择物料时显示当前可用库存（quantity - locked_quantity）

## 七、技术要点与注意事项
- **锁定库存机制**：审核时只锁定不扣减，完成时才真正扣减，这是 WMS 防超卖的关键设计。available = quantity - locked_quantity，审核前必须校验 available >= 出库数量。
- **两阶段扣减**：审核 lock → 完成 deduct，避免直接扣减导致出库单取消时库存回滚复杂；取消已审核单据只需 unlock 释放。
- **乐观锁双重保障**：lock/deduct/unlock 操作 UPDATE 时都带 `WHERE version=?`，version+1，防并发覆盖。M011 会再叠加 Redisson 分布式锁实现三重保障。
- **流水记录**：出库流水 change_type=2，before/after 准确记录，source_type=ORDER（工单领料）或 WMS（直接出库）。
- **取消逻辑分支**：待审核取消直接改状态；已审核取消必须释放锁定库存，否则 locked_quantity 永久占用。
- **库存不足提示**：抛 `BusinessException("物料[xxx]在货位[yyy]库存不足，可用[z]，需[a]")`，前端友好展示。
