# M024: 对话历史与上下文管理

> **所属阶段**：第四阶段 - AI 知识库问答
> **预计周期**：第 7 周
> **优先级**：P1
> **前置任务**：M023

## 一、任务目标
实现多轮对话上下文管理：保存对话历史（chat_session + chat_history 表），每次提问时携带历史上下文让大模型理解上下文，前端展示历史会话列表与对话记录，支持新建会话、切换会话、删除会话。

## 二、前置条件
- M023 已完成，AI 助手侧边栏可用
- M002 中 chat_session、chat_history 表已建好

## 三、详细执行步骤
### 步骤 1：编写会话与历史实体
在 `intellimes-ai`：
- `entity/ChatSession`（sessionId、title、userId）extends BaseEntity
- `entity/ChatHistory`（sessionId、role(user/assistant)、content、tokens）extends BaseEntity

### 步骤 2：编写会话管理服务
`ChatSessionService`：
- `createSession(userId)`：创建新会话，sessionId 用 UUID，title 默认"新对话"
- `listByUser(userId)`：查询用户所有会话（按更新时间倒序）
- `updateTitle(sessionId, title)`：更新会话标题（首次提问后自动生成标题）
- `deleteSession(sessionId)`：删除会话及其历史记录

### 步骤 3：编写历史记录服务
`ChatHistoryService`：
- `save(sessionId, role, content)`：保存一条消息
- `listBySession(sessionId, limit)`：查询会话最近 N 条历史
- `deleteBySession(sessionId)`：删除会话所有历史

### 步骤 4：改造 ChatService 携带上下文
```java
public String chatWithContext(String sessionId, String message) {
    // 1. 查询最近 10 条历史
    List<ChatHistory> history = chatHistoryService.listBySession(sessionId, 10);
    // 2. 构造 ChatClient 请求，注入历史
    ChatClient.ChatClientRequest spec = chatClient.prompt();
    for (ChatHistory h : history) {
        if (h.getRole().equals("user")) {
            spec = spec.user(h.getContent());
        } else {
            spec = spec.assistant(h.getContent());
        }
    }
    spec = spec.user(message);
    String answer = spec.call().content();
    // 3. 保存用户消息与 AI 回答
    chatHistoryService.save(sessionId, "user", message);
    chatHistoryService.save(sessionId, "assistant", answer);
    return answer;
}
```

### 步骤 5：改造流式接口携带上下文
`chatStream` 方法同样注入历史消息，流式输出后保存历史。

### 步骤 6：自动生成会话标题
首次提问后，调用大模型根据问题生成简短标题（如"关于 MES 的咨询"），更新 session.title，避免全部会话都叫"新对话"。

### 步骤 7：编写 Controller
`ChatSessionController`：
- `POST /ai/session` 创建会话
- `GET /ai/session/list` 当前用户会话列表
- `PUT /ai/session/title` 更新标题
- `DELETE /ai/session/{sessionId}` 删除会话
- `GET /ai/session/{sessionId}/history` 会话历史记录

### 步骤 8：改造 AI 助手前端
在 `ChatWindow.vue`：
- 左侧会话列表（标题、时间，可切换、删除）
- 顶部"新建会话"按钮
- 切换会话时加载对应历史记录
- 发送消息时传 sessionId
- 流式回答完成后保存到历史

### 步骤 9：上下文长度控制
- 历史记录只取最近 10 条（约 5000 token），避免超过模型 context window
- 超长历史可摘要压缩（可选高级功能）
- 单条消息超长截断

### 步骤 10：联调验证
- 新建会话，问"什么是 MES"，AI 回答
- 继续问"它有什么功能"（不提 MES），AI 理解"它"指 MES（上下文生效）
- 切换到新会话，问"它有什么功能"，AI 不知"它"指什么（无上下文）
- 会话列表显示标题（自动生成）
- 删除会话后历史记录同步删除

## 七、技术要点与注意事项
- **多轮对话价值**：用户提问常含指代词（"它""上面提到的"），无上下文 AI 无法理解；携带历史让 AI 理解上下文，提升交互自然度，是 ChatGPT 核心体验之一。
- **上下文长度控制**：大模型 context window 有限（如 8K/32K token），历史过多会超限报错且增加费用；只取最近 10 条是经验值，可按 token 数动态截断。
- **历史消息角色**：ChatHistory.role 区分 user/assistant，注入 ChatClient 时需按角色用 `.user()`/`.assistant()`，顺序不能错。
- **会话标题生成**：首次提问后用大模型生成标题（额外一次 API 调用），或截取问题前 20 字作为标题（低成本方案）。
- **历史持久化**：chat_session + chat_history 表存储，用户刷新页面或重新登录后历史仍在；对比内存存储更可靠。
- **并发安全**：同一会话多端登录同时提问，历史记录可能乱序，建议加 sessionId 锁或时间戳排序。
- **隐私与清理**：对话历史可能含敏感信息，提供删除功能；可设定定期清理策略（如 30 天前自动删除）。
