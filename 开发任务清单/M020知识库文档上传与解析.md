# M020: 知识库文档上传与解析

> **所属阶段**：第四阶段 - AI 知识库问答
> **预计周期**：第 7 周
> **优先级**：P0
> **前置任务**：M019

## 一、任务目标
实现知识库文档上传功能（支持 txt/md/pdf/word 格式），上传后解析提取文本内容，存入 `knowledge_doc` 表（status 初始为 0 待处理），为后续向量化与 ES 索引（M021）准备文档数据（参考计划书 4.3 knowledge_doc 表设计）。

## 二、前置条件
- M019 已完成，intellimes-ai 模块可用
- M002 中 knowledge_doc 表已建好
- 本机或对象存储（如 MinIO）可用于文件存储

## 三、详细执行步骤
### 步骤 1：配置文件上传
在 `application-dev.yml`：
```yaml
spring:
  servlet:
    multipart:
      max-file-size: 50MB
      max-request-size: 100MB
file:
  upload-path: ./uploads/knowledge/
```

### 步骤 2：编写 KnowledgeDoc 实体与 Mapper
在 `intellimes-ai`：
- `entity/KnowledgeDoc`（title、content LONGTEXT、fileType、filePath、status(0待处理1已索引2失败)、esIndexId）extends BaseEntity
- `mapper/KnowledgeDocMapper extends BaseMapper`

### 步骤 3：编写文件上传服务
`FileUploadService`：
- `upload(MultipartFile file)`：
  - 校验文件类型（txt/md/pdf/word）
  - 生成存储路径 `uploads/knowledge/yyyy/MM/dd/{uuid}.{ext}`
- `uploadAndParse(MultipartFile file, String title)`：
  - 调用 upload 存储文件
  - 调用 DocumentParser 解析文本
  - 保存 KnowledgeDoc（status=0 待处理，filePath=存储路径，content=解析文本）

### 步骤 4：编写文档解析器
`DocumentParser`：
- `parse(String filePath, String fileType) -> String`
- txt/md：直接读取文本
- pdf：用 Apache PDFBox 的 `PDDocument.load` 提取文本
- word(.docx)：用 Apache POI 的 `XWPFDocument` 提取段落
- word(.doc)：用 POI 的 `HWPFDocument`
- 异常时 status=2 失败，记录错误信息

### 步骤 5：引入文档解析依赖
在 `intellimes-ai/pom.xml`：
```xml
<dependency>
    <groupId>org.apache.pdfbox</groupId>
    <artifactId>pdfbox</artifactId>
    <version>3.0.x</version>
</dependency>
<dependency>
    <groupId>org.apache.poi</groupId>
    <artifactId>poi-ooxml</artifactId>
    <version>5.2.x</version>
</dependency>
```

### 步骤 6：编写知识库 Controller
`KnowledgeDocController`：
- `POST /ai/knowledge/upload`：上传文档（`@RequestPart MultipartFile file` + 标题参数）
- `POST /ai/knowledge/page`：分页查询文档列表
- `GET /ai/knowledge/{id}`：文档详情
- `DELETE /ai/knowledge/{id}`：删除文档（同步删 ES 索引，M021）
- `POST /ai/knowledge/reparse/{id}`：重新解析失败文档

### 步骤 7：编写前端 API 与页面
- `src/api/ai/knowledge.ts`：上传、列表、删除
- `src/views/ai/knowledge/index.vue`：
  - 上传区：`el-upload` 拖拽上传，支持多文件
  - 列表：标题、文件类型、状态（待处理/已索引/失败 tag）、上传时间、操作
  - 失败文档可重新解析
  - 详情弹窗：显示解析出的文本内容（前 1000 字预览）

### 步骤 8：联调验证
- 上传 test.txt（内容"MES 是制造执行系统..."）
- 上传 SOP.pdf（一份操作手册）
- 上传工艺.docx
- 查列表：3 条记录，状态待处理
- 点详情查看解析文本正确

### 步骤 9：异常处理
- 不支持文件类型：返回"仅支持 txt/md/pdf/word"
- 文件过大：返回"文件超过 50MB 限制"
- 解析失败：status=2，记录 errorMsg，可重新解析

## 六、验证方式
- 上传 txt/md 文件后解析文本正确存入 content
- 上传 pdf 文件后提取文本（中文不乱码）
- 上传 docx 文件后提取段落
- 不支持的类型（如 jpg）返回错误
- 状态流转：上传→待处理→（M021 索引后）已索引
- 列表分页、详情查看正常

## 七、技术要点与注意事项
- **knowledge_doc 表设计（计划书 4.3）**：status 字段流转 0 待处理 → 1 已索引（M021 完成）→ 2 失败；es_index_id 记录 ES 中的文档 ID，便于删除时同步清理 ES。
- **PDFBox 中文支持**：PDFBox 3.x 默认支持中文，但部分嵌入字体 PDF 需额外处理；解析时用 `PDFTextStripper` 提取文本，注意保留段落结构。
- **POI 内存**：大 Word 文件用 POI 解析占内存高，建议限制文件大小（50MB），或用流式 API（XSSF/SXSSF）。
- **文件存储路径**：按日期分目录 `yyyy/MM/dd/{uuid}.{ext}`，避免单目录文件过多影响性能；生产环境用 MinIO/OSS 对象存储。
- **文件类型校验**：不仅校验扩展名，还应校验文件头魔数（如 PDF 开头 `%PDF`），防止伪造扩展名上传恶意文件。
- **解析异步化**：大文件解析耗时长，建议上传后异步解析（用 `@Async` 或发 MQ 消息），避免阻塞上传接口；前端轮询或 WebSocket 通知解析完成。
- **文本清洗**：解析后文本可能含乱码、多余空白，建议清洗（去 HTML 标签、合并连续空格、去页眉页脚），提升后续检索质量。
