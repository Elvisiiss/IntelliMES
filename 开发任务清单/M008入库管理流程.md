# M008: 入库管理流程

> **所属阶段**：第二阶段 - WMS 仓储模块
> **预计周期**：第 3 周
> **优先级**：P0
> **前置任务**：M007

## 一、任务目标
实现完整的入库管理流程：入库单创建→审核→完成状态流转，完成时调用库存服务增加 `inventory` 表库存数量，并写入 `inventory_log` 流水（change_type=1 入库），前端提供入库单列表与表单页面，跑通"单据驱动库存增加"的核心 WMS 逻辑。

## 二、前置条件
- M007 已完成，仓库/库区/货位/物料基础数据可用
- M002 中 inbound_order、inbound_order_detail、inventory、inventory_log 表已建好
- M003 MyBatis-Plus 与事务基础就绪

## 三、详细执行步骤
### 步骤 1：编写入库单后端实体与 Mapper
在 `intellimes-wms`：
- `entity/InboundOrder`（orderNo、warehouseId、sourceType、sourceId、status、totalQuantity）extends BaseEntity
- `entity/InboundOrderDetail`（orderId、materialId、locationId、quantity）
- `mapper/InboundOrderMapper`、`InboundOrderDetailMapper extends BaseMapper`
- `InboundOrderMapper.xml`：联表分页查询（关联 warehouse、material 名称）

### 步骤 2：编写入库单 Service
`InboundOrderService`：
- `createOrder(InboundOrderDTO)`：生成入库单号（如 `IN20260801001` 按日期+序号），status=0 待审核，保存主表+明细
- `audit(Long id)`：状态 0→1 已审核
- `complete(Long id)`：状态 1→2 已完成，**核心**：事务内遍历明细调用 `InventoryService.increase(materialId, locationId, quantity)` 增加库存并写流水
- `cancel(Long id)`：状态 0/1 → 3 已取消
- `pageQuery` 分页查询

### 步骤 3：编写库存服务 InventoryService
`InventoryService`：
- `increase(materialId, warehouseId, locationId, quantity, sourceType, sourceId)`：
  - 查询 inventory 表是否存在该物料+货位记录
  - 不存在则 INSERT，存在则 UPDATE `quantity = quantity + ?`（用乐观锁 version）
  - 写入 `inventory_log`（change_type=1 入库，记录 before/after quantity）
- 用 `@Transactional` 保证库存与流水一致性

### 步骤 4：编写 InventoryLog 服务
- `InventoryLogService.save(log)` 写流水
- `pageQuery` 按物料/时间/变动类型查询

### 步骤 5：编写入库单 Controller
`InboundOrderController`：
- `POST /wms/inbound/page` 分页
- `POST /wms/inbound` 创建
- `PUT /wms/inbound/audit/{id}` 审核
- `PUT /wms/inbound/complete/{id}` 完成
- `PUT /wms/inbound/cancel/{id}` 取消
- `GET /wms/inbound/{id}` 详情（含明细）

### 步骤 6：编写前端 API 与页面
- `src/api/wms/inbound.ts`：封装上述接口
- `src/views/wms/inbound/index.vue`：列表（单号、仓库、来源、状态、数量、操作按钮）
- `src/views/wms/inbound/form.vue`：新增/编辑表单，支持动态添加多个明细行（物料下拉、货位下拉、数量）
- 状态流转按钮根据当前 status 动态显示（待审核→审核/取消；已审核→完成/取消）

### 步骤 7：联调验证入库流程
- 新增入库单（仓库 WH01，明细：物料 M001 螺丝 100 个 货位 A1-01）
- 审核入库单
- 完成入库单
- 查询 inventory 表，M001 在 A1-01 库存为 100
- 查询 inventory_log，有一条 change_type=1 记录

## 五、预期产出
- 完整的入库单生命周期（创建→审核→完成→取消）
- 入库完成自动增加库存并写流水
- 前端入库单管理页面（列表 + 表单 + 状态流转按钮）
- 为出库、移库、盘点等流程奠定库存操作基础

## 六、验证方式
- 创建入库单后 status=0，数据库有主表+明细记录
- 审核后 status=1
- 完成后 status=2，inventory 表对应物料库存增加，inventory_log 有 change_type=1 记录
- 重复完成接口返回业务异常"单据状态不允许操作"
- 取消已完成单据返回异常
- 前端列表状态列正确显示，按钮按状态动态显示

## 七、技术要点与注意事项
- **状态机校验**：每次状态流转必须校验当前状态是否允许目标状态，避免重复完成、非法取消，用 `BusinessException` 抛出。
- **事务一致性**：`complete` 操作涉及入库单状态更新 + 库存增加 + 流水写入三步，必须 `@Transactional` 包裹，任一步失败回滚。
- **库存 upsert**：inventory 表无该物料+货位记录时 INSERT，有时 UPDATE，可用 `ON DUPLICATE KEY UPDATE` 或先查后判断（依赖 uk_material_location 唯一索引）。
- **inventory_log before/after**：流水必须记录变动前后数量，便于追溯审计，after = before + change_quantity。
- **乐观锁**：库存 UPDATE 时 `WHERE id=? AND version=?`，version+1，防止并发覆盖（M011 会加分布式锁双重保障）。
- **单号生成**：建议 `IN + yyyyMMdd + 3位序号`，序号从 Redis 自增或 DB 序列表获取，避免并发重复。
