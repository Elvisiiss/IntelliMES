# M026: 单元测试与接口测试

> **所属阶段**：第五阶段 - 联调测试与部署
> **预计周期**：第 8 周
> **优先级**：P0
> **前置任务**：M025

## 一、任务目标
编写 JUnit 单元测试（重点覆盖库存扣减并发安全、工单状态流转等核心逻辑）与接口测试（用 Postman/HttpRunner 验证全部 REST API），生成测试报告，确保核心业务逻辑正确性与接口契约稳定，为上线提供质量保障。

## 二、前置条件
- M025 已完成联调，业务闭环可运行
- M011 已有并发测试基础
- 熟悉 JUnit 5、Mockito、Spring Boot Test

## 三、详细执行步骤
### 步骤 1：引入测试依赖
在 `intellimes-common/pom.xml` 或各模块 pom 添加：
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>mysql</artifactId>
    <scope>test</scope>
</dependency>
```

### 步骤 2：编写库存服务单元测试
`InventoryServiceImplTest`：
- `testIncrease`：入库增加库存，验证 quantity 与 inventory_log
- `testDeduct`：出库扣减库存，验证 quantity 减少与流水
- `testDeductInsufficient`：库存不足抛 BusinessException
- `testLockAndDeduct`：锁定后扣减，验证 locked_quantity 流转
- `testConcurrency`：50 线程并发扣减，验证无超卖（M011 用例完善）

### 步骤 3：编写工单状态流转测试
`ProductionOrderServiceImplTest`：
- `testCreate`：创建工单 status=0
- `testDispatch`：0→1 派工
- `testComplete`：1→2 完工，校验 completedQuantity
- `testClose`：2→3 关闭
- `testInvalidTransition`：非法状态流转抛异常（如 0→2 直接完工）
- `testUpdateCompletedQuantityConcurrency`：并发报工累加 completedQuantity

### 步骤 4：编写入库/出库单测试
`InboundOrderServiceImplTest`：
- `testCompleteIncreaseInventory`：入库完成增加库存
- `testCancelAfterAudit`：审核后取消
`OutboundOrderServiceImplTest`：
- `testAuditLockInventory`：审核锁定库存
- `testCompleteDeductInventory`：完成扣减库存
- `testCancelReleaseLock`：已审核取消释放锁定

### 步骤 5：编写消息消费者测试
`OrderCompletedConsumerTest`：
- `testHandleOrderCompleted`：模拟消息，验证入库单生成
- `testIdempotent`：重复消息不重复入库
- `testInventoryDeductConsumer`：领料消息触发出库

### 步骤 6：编写 AI 模块测试
`HybridSearchServiceTest`：
- `testBM25Search`：BM25 检索返回结果
- `testVectorSearch`：向量检索返回结果
- `testRRFMerge`：RRF 融合排序正确
- `testRagChat`：RAG 回答引用上下文

### 步骤 7：编写接口测试集合
用 Postman 或 HttpRunner 组织接口测试：
- 认证模块：登录、登出、刷新、获取用户信息
- WMS 模块：仓库/库区/货位/物料 CRUD、入库/出库/移库/盘点全流程
- MES 模块：车间/产线/工序 CRUD、工单全生命周期、报工质检
- AI 模块：文档上传、检索、RAG 问答
- 每个接口验证：状态码、业务码、数据结构、边界值

### 步骤 8：配置测试环境
- `application-test.yml`：用 H2 内存数据库或 Testcontainers MySQL
- Redis 用嵌入式 Redis 或 Testcontainers
- ES 与 RabbitMQ 可 mock 或用 Testcontainers
- 测试数据用 `@Sql` 或 `data.sql` 初始化

### 步骤 9：生成测试报告
- 执行 `mvn test` 生成 Surefire 报告
- 用 JaCoCo 生成代码覆盖率报告：
```xml
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
</plugin>
```
- 目标覆盖率：核心业务 70%+，工具类 80%+
- 报告输出到 `target/site/jacoco/index.html`

### 步骤 10：编写测试文档
在 `intellimes-backend/docs/test-report.md` 汇总：
- 单元测试用例数、通过数、失败数
- 接口测试用例数、通过率
- 代码覆盖率
- 发现的 bug 与修复情况
- 测试结论

## 七、技术要点与注意事项
- **测试金字塔**：单元测试（多）→ 集成测试（中）→ 端到端测试（少），单元测试快速反馈核心逻辑，端到端验证业务闭环。
- **核心逻辑优先**：库存扣减（并发安全）、工单状态流转（状态机）、消息消费（幂等）是项目最核心逻辑，测试覆盖率应最高。
- **Testcontainers 优势**：用真实 MySQL/Redis/ES 容器测试，比 mock 更接近生产环境，避免 mock 与真实行为不一致；启动慢但可靠。
- **测试隔离**：每个测试方法用 `@Transactional` + `@Rollback` 自动回滚，或每个测试类前清理数据，避免测试间相互影响。
- **Mock 外部依赖**：大模型 API 调用用 Mock（避免真实费用与不确定性），测试 RAG 逻辑时 mock EmbeddingService 与 ChatService。
- **接口测试自动化**：Postman 集合可用 Newman 命令行执行，集成到 CI/CD；HttpRunner 支持 YAML 编写便于版本管理。
- **覆盖率不是全部**：覆盖率 100% 不等于无 bug，关键看测试用例质量（边界值、异常场景、并发）；盲目追求覆盖率会写出无意义测试。
- **测试数据管理**：用 `@Sql` 加载初始数据或用 Factory 模式构造，避免硬编码；测试数据应覆盖正常、边界、异常三类场景。
