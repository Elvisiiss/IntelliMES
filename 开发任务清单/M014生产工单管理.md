# M014: 生产工单管理

> **所属阶段**：第三阶段 - MES 生产模块
> **预计周期**：第 5 周
> **优先级**：P0
> **前置任务**：M013

## 一、任务目标
实现生产工单全生命周期管理：工单创建→派工→状态流转（0-待派工→1-生产中→2-已完工→3-已关闭），管理优先级、计划时间，并在报工时更新 completed_quantity，前端提供工单管理页面（参考 production_order 表设计），为报工与 MES-WMS 联动奠定工单数据基础。

## 二、前置条件
- M013 已完成，车间/产线/工序可选
- M007 物料管理可用（工单产品关联物料）
- M002 中 production_order 表已建好

## 三、详细执行步骤
### 步骤 1：编写工单后端实体与 Mapper
在 `intellimes-mes`：
- `entity/ProductionOrder`（orderNo、productName、productMaterialId、quantity、completedQuantity、status、priority、planStartTime、planEndTime、workshopId、lineId、createBy）extends BaseEntity
- `mapper/ProductionOrderMapper` + XML：联表查询（关联 workshop、production_line、material）

### 步骤 2：编写工单 Service
`ProductionOrderService`：
- `createOrder`：生成工单号 PO20260801001，status=0 待派工，completedQuantity=0
- `dispatch`：0→1 生产中，记录派工时间、派工人
- `complete`：1→2 已完工，校验 completedQuantity >= quantity
- `close`：2→3 已关闭
- `updateCompletedQuantity(orderId, addQuantity)`：报工时累加已完成数量，用乐观锁防并发
- `pageQuery` 分页查询（按状态、工单号、产品名、车间筛选）

### 步骤 3：编写工单 Controller
`ProductionOrderController`：
- `POST /mes/order/page` 分页
- `POST /mes/order` 创建
- `PUT /mes/order/dispatch/{id}` 派工
- `PUT /mes/order/complete/{id}` 完工
- `PUT /mes/order/close/{id}` 关闭
- `GET /mes/order/{id}` 详情
- `GET /mes/order/listByStatus` 按状态查询（供报工选择生产中工单）

### 步骤 4：编写前端 API 与页面
- `src/api/mes/order.ts`
- `src/views/mes/order/index.vue`：
  - 列表（工单号、产品、计划数量、已完成、进度百分比、状态 tag、优先级、计划时间、操作）
  - 状态 tag 颜色：待派工灰、生产中蓝、已完工绿、已关闭红
  - 进度列用 `el-progress` 显示 completedQuantity/quantity 百分比
  - 操作按钮按状态动态显示
- `src/views/mes/order/form.vue`：创建表单（产品名、物料下拉、数量、优先级、计划起止时间、车间下拉、产线联动下拉）

### 步骤 5：编写工单详情页
`src/views/mes/order/detail.vue`：
- 顶部工单基本信息
- 报工记录列表（关联 work_report，M015 实现）
- 领料记录（关联出库单，M017 实现）

### 步骤 6：配置路由与菜单
- `/mes/order` 工单管理
- `/mes/order/detail/:id` 工单详情

### 步骤 7：联调验证
- 创建工单：产品"电机A"、物料 M003、数量 100、车间 WS01、产线 L1
- 派工：状态变为生产中
- 模拟报工调用 `updateCompletedQuantity` 加 30，进度变为 30%
- 完工：状态变为已完工
- 关闭：状态变为已关闭

## 五、预期产出

- 工单进度可视化（completedQuantity/quantity）

## 六、验证方式
- 创建工单 status=0，completedQuantity=0
- 派工后 status=1
- 调用 updateCompletedQuantity 后 completedQuantity 增加，进度更新
- 完工后 status=2，关闭后 status=3
- 非法状态流转（如待派工直接完工）返回业务异常
- 前端列表进度条与状态 tag 正确显示

## 七、技术要点与注意事项
- **工单状态机**：严格按 0→1→2→3 流转，不允许跳跃（如待派工不能直接完工），每次流转校验当前状态。
- **completedQuantity 并发更新**：多工人同时报工时并发累加 completedQuantity，必须用乐观锁 `UPDATE ... SET completed_quantity=completed_quantity+? WHERE id=? AND version=?`，避免覆盖。
- **完工校验**：完工时校验 completedQuantity >= quantity，未生产完不能完工（或允许部分完工，按业务定）。
- **优先级**：priority（1高 2中 3低），排产时按优先级排序，前端用 tag 颜色区分。
- **计划时间**：planStartTime/planEndTime 用于排产看板（M018）展示甘特图，需校验结束时间晚于开始时间。
- **工单号生成**：PO + yyyyMMdd + 3位序号，参考入库单号生成方式，Redis 自增序号防并发重复。
- **乐观锁复用**：工单表加 version 字段，与 inventory 表同理，updateById 时自动带 version 条件。
