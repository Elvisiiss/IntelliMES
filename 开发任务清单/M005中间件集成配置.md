# M005: 中间件集成配置

> **所属阶段**：第一阶段 - 基础架构
> **预计周期**：第 2 周
> **优先级**：P0
> **前置任务**：M004

## 一、任务目标
完成 Redis+Redisson、RabbitMQ、Elasticsearch 三大中间件的客户端配置与工具类封装：Redisson 分布式锁工具类 `RedissonDistributedLock`、RabbitMQ 的 `mes.topic`/`wms.topic`/`iot.topic` 三个 Exchange 与对应 Queue 的声明绑定、ES 客户端与索引初始化，为后续 WMS 并发库存扣减、MES 消息驱动入库、AI 知识库检索打下基础。

## 二、前置条件
- M004 已完成，Redis 已可用
- 本机已启动 RabbitMQ（默认端口 5672，管理界面 15672）与 Elasticsearch（9200）
- 已阅读计划书第五章「中间件应用场景详解」

## 三、详细执行步骤
### 步骤 1：配置 Redis + Redisson
在 `intellimes-common/pom.xml` 引入 `redisson-spring-boot-starter:3.25.x` 与 `spring-boot-starter-data-redis`。
在 `application-dev.yml` 写入：
```
spring:
  data:
    redis:
      host: localhost
      port: 6379
      password:
      database: 0
  redisson:
    config: |
      singleServerConfig:
        address: "redis://localhost:6379"
        database: 0
```
编写 `RedisConfig`：注册 `RedisTemplate`（key 用 String，value 用 Jackson 序列化）、`StringRedisTemplate`。

### 步骤 2：编写 RedissonDistributedLock 工具类
在 `com.intellimes.common.lock` 创建 `RedissonDistributedLock`：
- `boolean tryLock(String lockKey, long waitTime, long leaseTime, TimeUnit unit)`
- `void unlock(String lockKey)`
- 内部用 `redissonClient.getLock(lockKey)`，key 统一加前缀 `intellimes:lock:`
- 提供模板方法 `executeWithLock(lockKey, waitTime, leaseTime, Supplier<T>)` 自动加锁释放

### 步骤 3：配置 RabbitMQ 依赖与连接
引入 `spring-boot-starter-amqp`。`application-dev.yml` 写入：
```
spring:
  rabbitmq:
    host: localhost
    port: 5672
    username: guest
    password: guest
    virtual-host: /
    publisher-confirm-type: correlated
    publisher-returns: true
    listener:
      simple:
        acknowledge-mode: manual
        prefetch: 10
```

### 步骤 4：定义 RabbitMQ Exchange/Queue/Binding
在 `com.intellimes.common.mq` 创建 `RabbitMQConfig`：
- `mes.topic`（Topic Exchange）：绑定 Queue `mes.order.completed.queue`，routingKey `order.completed`
- `wms.topic`：绑定 Queue `wms.inventory.deduct.queue`，routingKey `inventory.deduct`
- `iot.topic`：绑定 Queue `iot.device.status.queue`，routingKey `device.status`
- 用 `@Bean` 声明 `TopicExchange`、`Queue`、`Binding`，队列设为 durable
- 定义常量类 `MQConstants` 存放 exchange/queue/routingKey 名称

### 步骤 5：编写 RabbitMQ 生产者工具
创建 `MQProducer`：
- `send(String exchange, String routingKey, Object message)` 同步发送
- `convertAndSend` + 消息体 JSON 序列化
- 配置 `Jackson2JsonMessageConverter` Bean 替换默认 Java 序列化

### 步骤 6：编写 RabbitMQ 消费者示例
在 `com.intellimes.common.mq.consumer` 创建 `DemoConsumer`：
- `@RabbitListener(queues = "mes.order.completed.queue")`
- `@RabbitHandler` 方法接收消息，手动 `channel.basicAck`
- 验证消费链路通畅（M016 会真正实现业务监听）

### 步骤 7：配置 Elasticsearch 客户端
引入 `spring-boot-starter-data-elasticsearch`。`application-dev.yml`：
```
spring:
  elasticsearch:
    uris: http://localhost:9200
    connection-timeout: 5s
    socket-timeout: 30s
```
编写 `ElasticsearchConfig`：注册 `ElasticsearchClient`（Spring Boot 3 自动装配，按需自定义 `RestClientOptions`）。

### 步骤 8：初始化 ES 索引
编写 `ESIndexInitializer`（实现 `ApplicationRunner`），启动时检查并创建索引：
- `knowledge_base`：字段 `title`(text)、`content`(text)、`embedding`(`dense_vector` dims 1024)、`doc_id`(keyword)、`create_time`(date)
- `production_logs`：字段 `level`、`message`(text)、`source`(keyword)、`timestamp`(date)
- 通过 `ElasticsearchClient.indices().create()` 创建，已存在则跳过

### 步骤 9：编写中间件健康检查
创建 `MiddlewareHealthController`：
- `GET /health/redis` ping redis
- `GET /health/mq` 检查 RabbitMQ 连接
- `GET /health/es` 检查 ES ping
- 启动应用后逐一验证

## 七、技术要点与注意事项
- **Redisson 分布式锁（计划书 5.3）**：`Rlock.tryLock(waitTime, leaseTime, unit)` 必须设 leaseTime 防止业务异常导致死锁；不要用 `lock()` 无参方法（默认 30s 看门狗续期，宕机场景有风险）。锁 Key 统一前缀 `intellimes:lock:` 便于监控。
- **RabbitMQ Exchange 设计（计划书 5.1）**：用 Topic Exchange 支持 routingKey 通配符，`order.completed`、`inventory.deduct`、`device.status` 三个核心场景，便于后续扩展 `order.*`、`inventory.*` 等模式订阅。
- **手动 ACK**：`acknowledge-mode: manual` 配合 `channel.basicAck` 防止消息丢失；消费异常时 `basicNack` 并决定是否重入队列。
- **消息序列化**：默认 Java 序列化跨语言不友好，必须配 `Jackson2JsonMessageConverter` 用 JSON。
- **ES dense_vector 维度**：`dims` 必须与所选 Embedding 模型输出维度一致（如 bge-large-zh 为 1024），建索引后无法修改，需提前确定。
- **ES 索引初始化幂等**：`ApplicationRunner` 中先 `indices().exists()` 判断，已存在跳过，避免重启报错。
- **连接超时**：ES 默认 socketTimeout 30s，向量检索大索引可能超时，按需调大。
